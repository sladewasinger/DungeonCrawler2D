## Added

- A reproducible 20-player real-server network load gate with simulation, transport, protocol, and memory evidence.
- Captured-packet JSON, MessagePack, and Protobuf assessment with a measured keep-JSON recommendation.
- Representative landscape phone and tablet geometry checks for the live mobile controls.

## Changed

- Local 2D movement now renders collision-aware partial-tick prediction for more immediate, fluid presentation.
- Remote interpolation follows a filtered server simulation timeline instead of packet-arrival time.
- Remote actors in both renderers now use a shared adaptive 75–160 ms jitter buffer, reducing stable-link presentation latency while retaining more history during irregular packet arrival.
- Remote interpolation reuses bounded frame records, and Three samples them once per rendered frame instead of running duplicate allocation-heavy passes.
- Remote interpolation now also recycles its warmed one-second snapshot history instead of allocating and discarding a sample record for every actor update.
- The 2D entity frame is partitioned once into reusable scene-owned buckets, renderer-view arrays, and ID sets instead of repeatedly filtering and allocating equivalent collections.
- Settled terrain and lighting chunk windows now skip rebuilding desired-coordinate arrays and sets on every rendered frame, while boundary crossings, rebakes, and rotations retain the existing streaming path.
- Torch synchronization reuses synchronous frame buffers and refreshes retained terrain-light seeds only when placed torches or the terrain instance actually change.
- Dynamic-light selection and visible torch-flame culling reuse bounded candidate/output buffers while preserving nearest-light priority and the personal-light guarantee.
- Idle live-HUD frames now reuse unchanged chat models and scan boss/toast state in place instead of rebuilding remote-entity, tab, line, toast, and completion collections every rendered frame.
- Live 2D HUD snapshots now reuse expensive inventory, crafting, stash, party, and status derivation between fixed simulation ticks while touch controls, prompts, compass, telemetry, ping, and FPS remain render-frequency updates.
- Live mobile action visuals and Phaser hit routing now share one geometry source with 44px-or-larger targets.
- Continuous 2D joystick drag now stays local until the fixed prediction/send tick instead of emitting browser-event-rate analog packets; release and action edges remain immediate.
- Fixed-tick input comparison now uses direct fields, and acknowledged prediction history reuses a bounded record pool instead of allocating comparison/filter arrays and prediction records throughout a session.

## Removed

- The fixed one-simulation-tick local-player rendering delay.

## Fixed

- Long-session movement degradation caused by accumulated projected-clock lead during reconciliation.
- Increasing 2D frame work caused by retained offscreen area tiles and their VFX/lighting rigs.
- Impossible projected input ticks reaching authoritative movement simulation.
- Release-note links and cache headers now target explicit static HTML objects instead of the game-shell fallback.
- Knife and other held weapons now show a directional animated guard pose while blocking.
- The 2D attack/block help now receives completed-action state, so each control disappears after it is demonstrated while the existing sixty-second fallback remains.
- Walk and sprint collision now sweeps each fixed step to the nearest legal wall contact instead of rejecting the whole step; nearby client/server prediction phases converge at the boundary rather than disagreeing by up to a full sprint step, and blocked-axis reconciliation stays pinned there.
- Reconciliation now preserves only the newest acknowledged catch-up step beyond an authoritative snapshot, preventing multi-step slow frames from snapping the local player backward by a full walk or sprint step while keeping projected clock lead bounded.
